# Backlog 2.4 (CANN-lite): why every attempt crashed, and a working version

Independent review, 2026-10-19. Nothing in `~/Projects/iaa-hackathon-2026` was changed; all
work is in `/tmp/iaa-staging/work/1019/cann/`.

## Root cause

glum cannot run in the same process as LightGBM in this venv. glum and tabmat bundle
their own copies of the LLVM OpenMP runtime, LightGBM links Homebrew's, and once both
sides are loaded, whichever library runs a parallel region second either segfaults or
deadlocks. Neither outcome produces a Python traceback, which is why the ledger had no
error text. The clash is specific to the tabmat/glum runtime against LightGBM's:
scikit-learn also bundles a libomp, it is loaded next to Homebrew's in every champion
run, and sklearn fits and LightGBM fits alternate without trouble (the champion itself,
and the `FL,FS,FL` line below). The rule to carry forward is that glum and LightGBM
cannot share a process.

The loaded images, listed from inside the harness process with `_dyld_get_image_name`
(`dyld_list.py`):

    after import lightgbm:  /opt/homebrew/Cellar/libomp/23.1.3/lib/libomp.dylib   (LightGBM, via @rpath)
                            .venv/.../sklearn/.dylibs/libomp.dylib                 (pulled in by lightgbm's sklearn import)
    after import glum:      .venv/.../tabmat/.dylibs/libomp.dylib
                            .venv/.../glum/.dylibs/libomp.dylib

Toy reproduction (`omp_test2.py`, 40k rows, 60 s alarm, loop PATH, `LOKY_MAX_CPU_COUNT=8`,
`python -I`; I = import, F = fit; L = LightGBM, G = glum):

    IL,IG,FG      rc=139  glum fit segfaults after LightGBM was imported first
    IG,IL,FL      rc=139  LightGBM fit segfaults after glum was imported first
    IL,IG,FL      rc=0    LightGBM alone is fine when it was imported first
    IG,IL,FG      rc=0    glum alone is fine when it was imported first
    IG,IL,FG,FL   rc=142  glum fits, then LightGBM hangs until the alarm kills it
    FL,FS,FL      rc=0    LightGBM then sklearn's TweedieRegressor then LightGBM: fine

Import order alone decides which side dies. `experiment.py` imports lightgbm at the top,
so any glum fit added to it is the losing side. `KMP_DUPLICATE_LIB_OK=TRUE` changes
nothing (the runtimes never detect each other; no "OMP Error #15" is printed).
`OMP_NUM_THREADS=1` avoids the crash but would also serialise LightGBM, so it is not a
fix for the loop.

Through the harness itself: the champion plus one glum fit at the start of
`fit_predict` (`exp_cann_glum.py`), run exactly as `loop.sh` runs the smoke test
(`python -I -m iaa.harness --smoke`, 300 s alarm, same PATH and env):

    rc=139 after 4 s; stderr holds only warnings; the last non-warning line is
    "  return DenseMatrix(a)", a line from a tabmat warning's traceback.

That is the ledger's "SMOKE CRASH ()" reproduced: `loop.sh` keeps the last line that
does not match `Warning|warn`, and a signal death leaves no such line.

## Why the earlier diagnoses missed it

The three ledger rows blamed on 2.4 are 10:46, 15:35 (CANN-lite) and 11:48 (a GLM blend
using glum). What they had in common was glum, which the 11:48 agent noticed; the 12:43
run swapped in sklearn and completed. But the diagnosis then moved on:

- The 11:48 error text, `raise child_exception_type(errno_num, err_msg, err_filename)`,
  is the last line of a traceback that loky prints for a *handled* exception (it could
  not find `sysctl` on the driver PATH, warned, and carried on with the logical core
  count). It was read as the crash. The PATH fix of 12:53 was right in itself but was
  not the cause, so the 15:35 retry "now that the environment bug is fixed" died the
  same way.
- At 10:46 and 11:48 the loop did not distinguish a timeout (rc 142) from any other
  failure; that branch came at 15:09. At 15:35 the exit code was not 142, and the
  "exit code N, no error text" fallback only came at 16:09, so the ledger row was empty
  again. A segfault still logs as "exit code 139, no error text" today.
- The smoke harness never saw a Python exception in any of the three, so there was
  nothing in `last_run.txt` to read. The pipeline review correctly said to run the smoke
  by hand; nobody had yet done so in a way that showed the exit code.

So the problem is the environment (glum's bundled OpenMP runtime against LightGBM's),
surfaced by the experiment code (glum chosen as the GLM library) and hidden by the
loop's error extraction, which cannot report a death by signal.

The CatBoost retry at 14:35 has the same empty signature (six encoder warnings, then
nothing), but it predates the timeout branch, so a 300 s overrun printed "()" too.
Three seeds of 1,200 CatBoost rounds on the smoke subsample fit that reading, and the
15:09 commit that added the timeout branch came right after it. CatBoost loads no
second libomp and its 23:54 run completed, so it is unrelated to the OpenMP clash.

## The fix

`exp_cann.py` is the champion (`HEAD:src/iaa/experiment.py`) with CANN-lite on
scikit-learn's GLMs instead of glum. scikit-learn's `TweedieRegressor` and
`PoissonRegressor` use the libomp that LightGBM already shares a process with (the
champion's own sklearn calls prove that), and the 12:43 run already showed they complete
inside the harness.

Per sub-model (motor BI frequency, motor other, buildings, contents), the same target and
weight the trees get are fitted by a ridge GLM (log link; Poisson for BI counts, Tweedie
1.1 for the rates) on a main-effects design:

- the credibility-encoded high-cardinality columns are used as they are (numeric);
- the remaining categoricals are one-hot with NaN as its own level, the modal train
  level as the base, unseen valid levels as all zeros;
- numerics: `log1p` when the 99th percentile exceeds ten times the median (premium,
  history costs), median imputation with a missing flag, standardised on train, clipped
  at ±5 sd;
- columns correlated above 0.995 with an earlier one are dropped (year_built vs
  property_age, policyholder_age vs customer_age, shared missing flags): without this
  the Hessian is singular and the solver falls back to an unconverged L-BFGS;
- the MONOTONE columns stay out of the GLM, so the owner's constraints still bind on the
  whole relativity (the trees are the only part that sees them);
- the design is float64; in float32 the Newton solver cannot meet its tolerance and
  falls back (seen in the first smoke).

The GLM linear predictor goes to LightGBM as `init_score`; prediction is
`exp(predict(raw_score=True) + eta_valid)` because `predict()` does not add it back.
`eta_valid` is clipped to the train range so an out-of-time drift cannot blow up the
level (the 12:43 sklearn blend scored fold B at -0.094 on motor, which looks like exactly
that). Seeds, encoder, EBM blend and anchoring are unchanged.

GLM alone on full fold B (`glm_diag.py`, Newton converged in 5-6 iterations, 4-8 s per
fit, no clipping needed, A/E as the champion's): motor 0.0707, buildings 0.1009,
contents 0.0676, against the champion's tree+EBM 0.0847 / 0.1104 / 0.0915. That is a
sane actuarial base model, and it is also the 3.1 "GLM reference" row the report lacks.

## Results

Smoke test under the loop's conditions: rc 0, 124 s (champion: 155 s on the same shared
box). Full fold A+B run through the harness with `--no-log`, `nice -n 10`, loop running
alongside: rc 0, 997 s wall (harness `seconds` 993; champion row 1096 s).

                     primary    fold A    fold B   motor B  buildings B  contents B
    champion dba2f36  0.13890   0.13696   0.13987   0.08474    0.11035     0.09150
    CANN-lite         0.13882   0.13800   0.13922   0.08377    0.11045     0.09008
    difference       -0.00008  +0.00104  -0.00065  -0.00097   +0.00010    -0.00142

Harness verdict: discard. Fold A gains a little, fold B loses a little, both inside
the 0.002 floor and inside single-seed noise (0.0026). A/E per line is identical to the
champion's, as anchoring guarantees. The backlog expected "neutral to small gain" and
got neutral: the credibility encoder, 1,200 rounds of 15-leaf trees and the EBM already
carry the smooth main effects, so a GLM starting point only changes where the trees
begin, and after 1,200 rounds they end in much the same place. The run itself is clean
(no solver fallbacks, no eta clipping, no warnings beyond the champion's own EBM ones).

What it does buy: the item is unblocked and no longer costs iterations; the loop could
re-run it with a weaker tree correction (fewer rounds or stronger shrinkage, since the
GLM already carries the level and main effects) or log the GLM part as the 3.1
reference row. I would not expect either to clear the keep bar.

## What the loop should change

`scripts/loop.sh` should always record the exit code, and name a signal when
`rc > 128` (139 = SIGSEGV, 142 = SIGALRM, 137 = SIGKILL). "exit code 139, no error
text" is accurate but sends the agent looking for a Python bug. `program.md` should say
that glum cannot be used in `experiment.py` (OpenMP clash with LightGBM in this venv),
and the backlog entry for 2.4 and 2.7 should point to sklearn's GLMs. If glum is wanted
for the GLM reference run (3.1), run it in its own process, with lightgbm not imported.

## A real neural CANN

Not started, as asked. torch 2.14.1 with MPS is in `~/.cache/iaa-gpu/.venv`, a different
venv from the harness, so a neural CANN cannot run inside `experiment.py` anyway; it
would follow the TabM route (`scripts/tabm_fit.py`, predictions saved per fold, blended
by the owner). Scale from backlog 4.1: TabM took 32 minutes on Metal for one fold with
early stopping after four epochs, so a GLM-skip network of similar size is about an hour
for folds A and B plus a final fit, two to three hours with three torch seeds (3.31).
TabM's gain came on property (buildings +0.0086, contents +0.0059 in fold B) and the
EBM blend has since taken part of that, so a second network would mainly add diversity
to a blend that already has a neural member at a weight the owner fixed. What a CANN
adds beyond TabM is the GLM skip connection, which reads as a tariff plus a correction
and would be the Part 2 transfer story. Since CANN-lite in the loop costs nothing, I
would run it there first and put the neural CANN on the GPU track after Thursday,
unless the TabM rerun on the EBM champion disappoints.
